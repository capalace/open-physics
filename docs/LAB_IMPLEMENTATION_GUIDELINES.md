# Open Physics 물리 실험실 구현 가이드라인

> **상태:** 물리 영역 확장의 필수 기준  
> **기준 구현:** 현재 역학 실험실과 자유 놀이터  
> **적용 영역:** 전자기학, 파동, 빛, 열, 현대물리

## 1. 목표

새 영역은 역학 화면의 색과 제목만 바꾸는 복제본이 아니다. 각 영역은 고유한 물체·원천·매질·장치·관찰 표현을 가지며, 사용자가 직접 조건을 바꾸어 물리 관계를 발견하는 하나의 **Subject Experience**를 제공한다.

각 영역의 완성 조건은 다음과 같다.

- 준비된 모든 콘텐츠가 서로 다른 질문과 장치를 가진 안내형 물리 실험실이다.
- 각 실험은 사용자가 Canvas에서 핵심 변수를 직접 조작한다.
- 각 실험은 가장 중요한 관계 하나를 단위가 있는 그래프로 보여준다.
- 핵심 장치는 보호하고 질문과 관계없는 설정은 숨긴다.
- 같은 선택 목록에 `빈 실험실 만들기`를 두고 영역의 핵심 현상을 재구성할 수 있게 한다.
- 물리 계산은 표시용 숫자가 아니라 장면 상태와 시각화 결과를 실제로 결정한다.

## 2. 역학에서 유지할 제품 구조

안내형 물리 실험실 하나는 다음 일곱 요소를 모두 가진다.

1. **탐구 질문:** 예 또는 아니오로 끝나지 않고 조건을 바꾸어 비교하게 한다.
2. **준비된 장치:** 현상을 알아볼 수 있는 고유한 물체와 배치를 제공한다.
3. **세 단계 조작:** `잡기 → 바꾸기 → 비교하기`처럼 Canvas 행동을 짧게 안내한다.
4. **직접 조작:** 핵심 독립 변수를 숫자 입력보다 손잡이, 위치, 각도, 연결, 원천 이동으로 바꾼다.
5. **관찰 포인트:** 움직임, 장, 파면, 광선, 입자 분포, 에너지 변화 중 무엇을 볼지 한 문장으로 말한다.
6. **실험 그래프:** 질문의 답을 판단할 물리량만 제목·축·단위·범례·현재값과 함께 표시한다.
7. **연결되는 법칙:** 쉬운 설명과 핵심 식을 함께 보여주되, 식 자체를 조작 UI로 사용하지 않는다.

프리셋은 이 일곱 요소 중 `준비된 장치와 시작 상태`만 담당한다. 프리셋 이름만 다른 장면은 별도 실험으로 세지 않는다.

## 3. 어린이도 사용할 수 있는 조작 기준

- 첫 화면에서 무엇을 잡아야 하는지 색이 있는 손잡이나 움직일 수 있는 물체로 드러낸다.
- 핵심 조작 대상의 최소 포인터 영역은 24px, 일반 버튼의 최소 높이는 40px로 한다.
- 기본 선택지는 `약하게·보통·강하게`, `차갑게·따뜻하게·뜨겁게`처럼 결과를 예상할 수 있는 말로 제시한다.
- 전압, 주파수, 굴절률처럼 필요한 용어는 유지하되 바로 옆에 한 문장 설명과 단위를 둔다.
- 정확한 수치 입력은 기본 흐름에서 숨기고 빈 실험실의 고급 설정으로만 제공한다.
- 설정을 바꿀 때 장면 전체를 임의로 초기화하지 않는다. 시작 상태로 돌아가는 행동은 `처음으로`가 전담한다.
- 반복 비교가 핵심인 실험은 조작하거나 놓는 순간 자동으로 실행한다. 배치 중인 빈 실험실은 의도하지 않은 운동을 막기 위해 멈춤 상태를 유지한다.
- 무작위 초기 배치는 사용하지 않는다. 새로고침과 `처음으로`는 같은 장면을 만든다.
- 화면에 보이는 원천, 경계, 광학 소자, 측정기와 실제 계산 위치가 항상 일치해야 한다.

## 4. 분야별 고유 시각 언어

공통 레이아웃은 유지하되 현상에 맞는 표현을 선택한다.

| 영역 | 직접 조작 대상 | 필수 시각 표현 | 피해야 할 대체 표현 |
|---|---|---|---|
| 전자기학 | 전하, 전극, 전선, 자석, 코일 | 장선·전위·전류 흐름·자기장·유도 방향 | 힘 계산 없이 움직이는 반짝임 |
| 파동 | 파원, 진폭 손잡이, 주파수, 경계, 관찰자 | 파면·중첩·마디·진폭·소리 파형 | 녹화된 사인파 애니메이션 |
| 빛 | 광원, 거울, 경계면, 렌즈, 슬릿 | 실제 교점까지 이어지는 광선·법선·상·스펙트럼·무늬 | 장식용 빛줄기와 고정된 상 |
| 열 | 열원, 입자, 용기, 피스톤, 단열 경계 | 입자 속도 분포·에너지 이동·상태 변화·P-V 경로 | 온도에 따라 색만 바뀌는 상자 |
| 현대물리 | 속도 손잡이, 광자, 에너지 준위, 장벽, 핵 | 시공간 비교·검출 사건·확률 분포·준위 전이·붕괴 통계 | 고전 입자 궤도로 양자 현상을 단정하는 표현 |

벡터가 자연스러운 전기장·자기력에는 화살표를 쓰고, 파동과 빛에는 파면·광선, 열에는 입자와 분포, 양자 현상에는 확률과 검출 결과를 쓴다. 역학의 속도 화살표를 모든 영역에 억지로 재사용하지 않는다.

## 6. 깊은 모듈 구조

물리 영역 하나는 작은 외부 인터페이스 뒤에 콘텐츠, 상태 변화, Canvas 상호작용, 렌더링을 숨기는 깊은 **Module**이다. 앱 셸은 영역 내부의 물리 모델이나 장치 종류를 알아서는 안 된다.

```text
SubjectExperience interface
        │
        ├── Mechanics adapter
        ├── Electromagnetism adapter
        ├── Waves adapter
        ├── Light adapter
        ├── Thermal adapter
        └── Modern Physics adapter
```

공통 셸이 알아야 하는 외부 인터페이스는 다음 책임으로 제한한다.

- 영역 식별자, 사용자 표시 이름과 안내 실험 목록 제공
- 기본 안내 실험 또는 빈 실험실 활성화
- 실행·일시정지·한 단계·처음으로 처리
- Canvas와 실험 선택·안내·조건·그래프 호스트에 mount/unmount
- 창 크기 변경 처리

영역별 물체 타입, 방정식 매개변수, 포인터 상태, 렌더링 세부사항은 인터페이스 밖으로 노출하지 않는다.

### 폴더와 파일 소유권

```text
src/app/subjects/
├── subject-experience.ts          # 공통 계약, 통합 브랜치만 수정
├── mechanics-adapter.ts           # 기존 역학 연결, 통합 브랜치만 수정
├── electromagnetism/              # 전자기학 브랜치 전용
├── waves/                         # 파동 브랜치 전용
├── light/                         # 빛 브랜치 전용
├── thermal/                       # 열 브랜치 전용
└── modern/                        # 현대물리 브랜치 전용
```

분야별 브랜치는 자기 폴더와 필요한 `src/physics/laws/<영역>.ts` 및 대응 테스트만 수정한다. `index.html`, `src/app/main.ts`, `src/app/style.css`, 공통 계약과 다른 분야 폴더는 수정하지 않는다. 공통 셸 연결과 공용 스타일 통합은 모든 분야 브랜치를 합친 뒤 통합 브랜치에서 한 번만 수행한다.

### 분야 내부 권장 구조

```text
<subject>/
├── catalog.ts       # 질문, 세 단계 조작, 관찰, 허용 조건, 법칙
├── models.ts        # 렌더러와 무관한 상태·계산 Module
├── experience.ts    # SubjectExperience adapter와 수명주기
├── renderer.ts      # Canvas 표현과 hit testing
├── style.css        # 영역 전용 class 아래로 한정한 스타일
└── *.test.ts        # 카탈로그, 모델, 직접 조작, 결정론 회귀 테스트
```

파일 수는 구현에 맞게 줄일 수 있지만 콘텐츠 정의, 순수 계산, Canvas adapter의 책임은 섞지 않는다.

## 7. 빈 실험실 기준

각 영역의 `빈 실험실 만들기`는 빈 화면이 아니라 가장 작은 유효 월드와 팔레트를 제공한다.

- 전자기학: 양·음전하, 도선·전지·저항, 자석·코일, 전기장·전위 측정
- 파동: 파원, 경계, 줄·매질, 두 번째 파원, 관찰자·검출기
- 빛: 광원, 거울, 매질 경계, 렌즈, 프리즘, 슬릿, 스크린
- 열: 입자 용기, 열원·냉각원, 전도체·단열체, 피스톤, 온도계
- 현대물리: 광자원, 금속 표면, 에너지 준위 원자, 장벽, 검출기, 핵 표본

팔레트에서 추가한 대상은 화면 그림과 실제 모델에 동시에 등록되고, 삭제 시 관련 연결·측정·장도 함께 정리된다. 안내 실험에서 빈 실험실로 이동할 때 준비된 장치를 가져오지 않는다.

## 8. 그래프와 측정 기준

- 시간 변화가 핵심이면 가로축을 시간으로 쓴다.
- 입력 조건 비교가 핵심이면 거리, 각도, 주파수, 온도, 전압처럼 질문에 맞는 가로축을 쓴다.
- 파형·스펙트럼·확률 분포·P-V 선도는 모두 `Experiment Graph`이지만 선 그래프 모양을 강제하지 않는다.
- 단위 없는 값은 `상대 세기`, `확률`, `정규화 값`처럼 의미를 명시한다.
- 같은 색은 Canvas의 대상, 범례, 그래프 선에서 같은 대상을 뜻한다.
- 그래프는 실행 상태를 추측하지 않고 영역 Module이 제공한 snapshot만 그린다.

## 9. 물리 모델 기준

- `docs/PHYSICS_MODELS.md`의 식과 가정을 기준으로 하며 단순화는 실험 설명에 드러낸다.
- 기존 `src/physics/laws` 계산을 우선 재사용하고, 빠진 식만 작은 순수 함수나 상태 Module로 추가한다.
- 장면 애니메이션이 방정식 결과를 흉내 내지 않는다. 같은 모델 결과가 위치, 색, 장선, 파면, 광선, 입자, 그래프에 함께 반영되어야 한다.
- 물리 법칙과 수치 solver를 분리한다. 시간 전개가 필요 없는 정적 관계는 억지로 프레임 solver에 넣지 않는다.
- 0으로 나누기, 정의되지 않는 각도, 빛보다 빠른 속도, 음의 절대온도처럼 모델 밖의 입력은 명시적으로 제한한다.
- 교육용 축척과 실제 SI 값의 변환을 한곳에 두고 Canvas 픽셀을 식에 직접 섞지 않는다.

## 10. 테스트와 완료 기준

분야별 브랜치는 다음 검증을 자체적으로 통과해야 한다.

1. 카탈로그에 기준 목록의 모든 실험이 정확히 한 번씩 존재한다.
2. 모든 실험이 고유한 질문, 세 단계 조작, 관찰 포인트, 법칙, 그래프를 가진다.
3. 핵심 계산은 Canvas 없이 입력과 결과를 검증할 수 있다.
4. 대표 실험의 포인터 조작이 실제 독립 변수를 바꾸고 결과 시각화·그래프를 함께 바꾼다.
5. `처음으로`와 새로고침은 결정론적인 같은 상태를 만든다.
6. 안내형 실험에서 핵심 장치를 삭제할 수 없고 관련 조건만 노출된다.
7. 빈 실험실에서 영역의 핵심 원천·대상·매질·측정기를 추가·이동·삭제할 수 있다.
8. 영역 전용 테스트, 전체 `npm test -- --run`, `npm run build`가 통과한다.
9. 실제 브라우저에서 영역 전환, 첫 실험, 직접 조작, 그래프, 빈 실험실을 확인한다.

테스트는 내부 필드보다 외부 인터페이스를 통과한 관찰 결과를 우선 검증한다. 구현 리팩터링만으로 깨지는 테스트보다 사용자가 보는 장면과 결과를 설명하는 테스트를 남긴다.

## 11. 병렬 작업 규칙

- 모든 분야 브랜치는 같은 가이드라인·공통 계약 커밋에서 시작한다.
- 워크트리 하나는 분야 하나만 소유한다.
- 분야 브랜치는 다른 분야의 커밋을 병합하거나 공통 셸을 선점하지 않는다.
- 공통 기능이 필요하면 자기 브랜치에서 임시 복제하지 않고 통합 브랜치에 필요한 인터페이스 변경을 기록한다.
- 각 분야는 테스트와 conventional commit을 마친 SHA를 통합 담당자에게 전달한다.
