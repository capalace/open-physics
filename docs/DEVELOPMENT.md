# Open Physics 개발 현황 및 기본 아키텍처

> 이 문서는 현재까지 구현한 물리 엔진과 웹 Playground의 상태를 기록하는 개발 기준 문서다.

## 1. 프로젝트 목표

Open Physics는 브라우저에서 물리학을 시각적으로 실험할 수 있는 2D 인터랙티브 물리 시뮬레이션 프로젝트다.

핵심 목표는 실제 세계의 모든 물리 현상을 정밀하게 재현하는 것이 아니다. 사용자가 물체와 환경을 직접 조작하면서 **물리학의 공식과 관계를 시각적으로 이해하고 실험할 수 있는 공간**을 만드는 것이다.

주요 원칙:

- 백엔드 없이 프론트엔드에서 시뮬레이션을 실행한다.
- 기본 공간은 2D로 한다.
- 물리 엔진은 실제 물리의 완전한 재현보다 교육적이고 가정된 물리 모델을 우선한다.
- 공식과 물리 법칙을 명시적인 코드 단위로 관리한다.
- 같은 물리 공간 안에서 객체를 자유롭게 추가하고 이동할 수 있어야 한다.
- 학습 단계에 따라 사용할 물리 법칙을 제한하거나 활성화할 수 있어야 한다.
- 설명 UI와 물리 엔진을 분리한다.

## 2. 콘텐츠 영역

전체 콘텐츠의 큰 분류는 다음과 같다.

1. 역학
2. 전자기학
3. 파동
4. 빛
5. 열
6. 현대물리

교육과정은 제품의 절대적인 제약이 아니라 콘텐츠를 단계적으로 제공하기 위한 가이드라인으로 사용한다.

## 3. 물리 모델의 기본 철학

Open Physics의 물리 엔진은 '실제 세계와 똑같은 물리엔진'을 목표로 하지 않는다.

예를 들어 중력은 일반적인 시뮬레이션 상황에서 다음과 같은 공식으로 표현할 수 있다.

```text
F = mg
```

객체에 작용하는 힘을 계산하고,

```text
a = F / m
```

을 통해 가속도를 얻은 뒤 solver를 통해 속도와 위치를 갱신한다.

이 구조를 유지하면서 사용자가 학습 단계에 따라 활성화할 물리 법칙을 선택할 수 있도록 한다.

## 4. 엔진 구조

현재 물리 코어는 다음 구조를 가진다.

```text
PhysicsSimulation
│
├── Bodies
│   ├── position
│   ├── velocity
│   ├── acceleration
│   ├── mass
│   ├── radius
│   ├── restitution
│   └── fixed
│
├── Laws
│
├── Fields
│
├── Constraints
│
├── Collision
│
└── Solver
```

### 4.1 Body

물리 공간 안에서 움직이는 객체다.

기본 상태에는 위치, 속도, 가속도, 질량이 포함된다.

시각화 객체는 물리 객체와 분리한다. 따라서 Canvas 렌더링을 변경하더라도 물리 코어 자체는 변경하지 않는 것을 원칙으로 한다.

### 4.2 Force Law

특정 물리 법칙을 힘 계산으로 표현한다.

예:

```text
중력
스프링
마찰
전기력
```

법칙은 가능한 한 공식 단위로 독립적인 테스트를 작성한다.

### 4.3 Spatial Field

객체에 직접 붙는 것이 아니라 공간에 존재하는 물리적 환경이다.

현재 구현된 대표적인 Field:

```text
UniformGravityField
PointGravityField
UniformElectricField
UniformMagneticField
```

예:

```text
Uniform gravity
F = mg

Electric field
F = qE

Magnetic field
F = q(v × B)
```

이 구조를 이용하면 사용자가 특정 공간에 전기장이나 중력장을 배치하고 객체를 그 안으로 가져가는 방식의 인터랙션을 구현할 수 있다.

### 4.4 Constraint

객체 사이의 관계를 유지하는 제약조건이다.

현재는 거리 제약을 지원한다.

향후 다음과 같은 기능으로 확장할 수 있다.

- 줄
- 막대
- 진자
- 관절
- 도르래

### 4.5 Collision

객체가 서로 겹치는 경우 충돌 법선과 상대 속도를 계산하고 impulse를 적용한다.

현재 기본적인 원형 반지름 기반 충돌과 반발계수(restitution)를 사용한다.

반발계수는 엔진 내부 물리량으로 유지하되 Playground에서는 직접 노출하지 않는다. 사용자는 고무, 나무, 금속, 점토 같은 교육용 재질 프리셋을 선택하고, 각 재질이 내부 반발계수로 변환된다. 이 재질은 실제 물질의 모든 성질을 재현하는 것이 아니라 충돌 반응을 쉽게 예상하게 하는 단순 모델이다.

## 5. Simulation Pipeline

물리 시뮬레이션의 실행 순서는 명확하게 분리한다.

```text
1. Force Evaluation
   Laws + Fields
        ↓
2. Integration
   Solver
   F → a → v → x
        ↓
3. Constraints
        ↓
4. Collision
        ↓
5. Advance Time
```

이 순서는 중요한 아키텍처 규칙이다.

특히 이전 구현에서 사용했던 작은 timestep을 이용한 임시 충돌 처리나 시간 rollback 같은 우회 방법은 사용하지 않는다. 충돌과 제약조건은 명시적인 pipeline 단계에서 처리해야 한다.

## 6. Solver

현재 코어에는 기본 Euler 계열 적분 구조가 있다.

향후 Solver를 교체 가능한 전략으로 확장한다.

```text
Solver
├── Euler
├── Semi-Implicit Euler
├── Verlet
└── RK4
```

목적은 물리 정확도 자체를 무조건 높이는 것이 아니라, 각 시뮬레이션 상황에서 안정성과 이해 가능성을 확보하는 것이다.

## 7. 테스트 원칙

물리 공식과 핵심 엔진 기능은 구현과 함께 테스트한다.

현재 테스트 범위에는 다음이 포함된다.

- 다중 객체의 힘 적용
- 충돌 impulse
- 거리 constraint
- 균일 중력장
- 점질량 중력장
- 균일 전기장
- 균일 자기장
- 방사형 field 계산

향후 모든 물리 법칙은 가능한 경우 다음 구조를 따른다.

```text
법칙 구현
   ↓
공식 단위 테스트
   ↓
시뮬레이션 통합 테스트
   ↓
시각적 Playground 검증
```

## 8. 브라우저 Playground

웹 애플리케이션은 물리 코어와 UI를 분리한다.

```text
src/
├── physics/
│   ├── core.ts
│   ├── quantities.ts
│   ├── world.ts
│   ├── fields.ts
│   ├── simulation.ts
│   └── laws/
│
└── app/
    ├── physics-playground.ts
    ├── main.ts
    ├── index.html
    └── style.css
```

`PhysicsPlayground`는 브라우저 입력과 Canvas 렌더링을 물리 코어에 연결하는 adapter 역할을 한다.

현재 Playground에서 지원하는 기능:

- 반응형 3패널 인터페이스: 실험 선택 / 물리 월드 / 속성 편집
- 어린이도 바로 사용할 수 있는 행동 중심 문구와 큰 선택 버튼
- 재질·무게는 쉬운 프리셋을 기본으로 제공하고 정확한 수치 입력은 접어서 숨기는 점진적 공개
- 자유 낙하, 포물선 운동, 충돌 실험 프리셋
- 실행 / 일시정지 / 단일 프레임 진행 / 초기화
- 원형 물체 추가, 선택, 드래그, 삭제
- 선택 물체의 이름, 색상, 질량, 재질 편집과 운동 화살표 조작
- 무중력, 달, 지구, 목성 중력 환경 선택
- 바닥·천장·좌우 벽 경계 충돌
- 충돌 실험 프리셋의 약한 운동 감쇠와 저속 정지 처리
- 이동 궤적과 속도·가속도 벡터
- 고정 timestep과 SI 단위/화면 좌표 변환
- 키보드 조작: Space 실행/멈춤, 방향키 오른쪽 단일 진행, Delete 삭제

설정 변경은 전체 월드를 자동 초기화하지 않는다. 프리셋 변경만 새 시작 상태를 불러오며, 재질·무게·중력은 현재 상태에 즉시 적용한다. 운동 화살표를 조작할 때는 재현 가능한 관찰을 위해 시뮬레이션을 자동으로 일시정지한다.

첫 번째 역학 수직 슬라이스는 다음 제품 흐름을 구현한다.

```text
프리셋 선택
  ↓
객체 선택·배치·편집
  ↓
물리 조건 변경
  ↓
실행
  ↓
충돌·운동 계산
  ↓
궤적·벡터 관찰
  ↓
조건을 바꾸고 다시 실험
```

## 9. Frontend Build

프론트엔드는 Vite + TypeScript 기반으로 구성한다.

```text
TypeScript
    ↓
Vite
    ↓
dist/
    ↓
GitHub Pages
```

`vite.config.ts`의 Pages base 경로는 다음과 같다.

```text
/open-physics/
```

개발 명령:

```bash
npm install
npm run dev
```

빌드:

```bash
npm run build
```

테스트:

```bash
npm test
```

`package-lock.json`은 실제 npm dependency resolution 결과를 저장하며, CI와 로컬 검증은 동일한 의존성 버전을 사용한다. CI에서는 `npm ci`로 lockfile을 엄격하게 적용한다.

## 11. 교육 단계와 물리 법칙

Open Physics의 핵심 UX는 하나의 물리 공간에서 객체가 실제로 법칙의 영향을 받되, 사용자의 학습 단계에 따라 활성화되는 법칙의 범위를 조절하는 것이다.

예:

```text
초기 역학
→ 중력 + 기본 운동

확장 역학
→ 힘 + 마찰 + 스프링 + 충돌

전자기학
→ 전하 + 전기장 + 자기장

파동
→ 파동장

빛
→ 광선 + 반사 + 굴절

현대물리
→ 광자 + 원자 + 핵 + 상대론적 모델
```

중요한 것은 서로 다른 앱을 만드는 것이 아니라 **동일한 물리 공간에서 활성 법칙 집합만 변경하는 것**이다.

## 12. 향후 개발 우선순위

현재 단계 이후의 우선순위는 다음과 같다.

1. Solver pipeline을 완전히 독립된 컴포넌트로 정리
2. 충돌 시스템 강화
3. Body / Shape API 정리
4. 물리 객체 생성 및 편집 UX 개선
5. 프리셋 시스템
6. 법칙 활성화 단계 시스템
7. 역학 콘텐츠 확장
8. 전자기학 / 파동 / 빛 / 열 / 현대물리 확장
9. 시각화 요소 강화
10. 교육용 실험 시나리오 추가

## 13. 개발 원칙 요약

```text
물리 공식
   ↓
독립적인 Law / Field
   ↓
PhysicsSimulation
   ↓
Solver Pipeline
   ↓
물리 상태
   ↓
Renderer
   ↓
사용자 인터랙션
```

물리 엔진과 콘텐츠 설명을 섞지 않는다.

물리 공식은 테스트 가능한 코드로 만든다.

시뮬레이션은 백엔드 없이 브라우저에서 실행한다.

2D를 기본으로 하고, 3D는 필요성이 확인된 뒤 별도로 검토한다.

교육과정은 콘텐츠 구조를 위한 참고자료이지 물리 엔진의 구조적 제약이 아니다.
